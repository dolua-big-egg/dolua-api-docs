# 工程与脚本包

**文档版本** `1.3.1`

doLua 工程是 **一层文件夹**：里面有入口脚本、可选的用户模块、配置和资源。配套工具把它打成设备能识别的脚本包再烧进去。底层虽按 A/B 两槽设计，**当前版本未启用双槽切换**，见 [runtime.md 第 2 节](runtime.md#2-脚本副本a--b-两槽)。

本篇只讲 **进设备之后** 这份包里有什么、用户模块怎样才能 `require` 到。侧边栏怎么认工程、五区怎么勾选、LUAPK 怎么生成，见 [工程结构](../dolua-assisant/project-structure.md)，这里不再抄一遍。虚拟机如何跑这份包见 [runtime.md](runtime.md)；NT26 配额见 [资源](../dolua-api/nt26/resources/README.md)。

## 1. 仓库和工程不是同一层

配套工具里的 **Lua workspace**（以及 demo 根）是仓库：下面可以有很多工程，每个工程单独一层目录。入口脚本必须写在含工程标志的那一层里面，不要摊在仓库根。细则、扫描截断、描述文件名字见 [工程结构](../dolua-assisant/project-structure.md)。

官方可导入例程在文档仓的 `examples/nt26/`，每个子目录就是一份工程。

---

## 2. 进设备的几类文件

设备真正跑起来的是脚本包里的内容，不是工程文件夹的完整拷贝：

| 进包的 | 到设备上做什么 |
| --- | --- |
| 入口脚本 | 虚拟机启动后跑的那一份 |
| 已登记的用户模块 | 按需 `require` |
| 当前选中的开机配置 | 开机解析，**不是** `require` |
| 已勾选的内置资源 | 进内部存储，占该型号共享配额 |

侧边栏「主文件 / 模块 / 配置 / 内置 / 其他」怎么勾、LUAPK 怎么打，见 [工程结构](../dolua-assisant/project-structure.md)。**不要**手改工程标志 JSON。

---

## 3. 用户模块怎样才能 require 到

三件事必须同时成立：

1. 文件在工程文件夹里，且登记在 **模块** 分区。
2. `require` 的名字 = 文件名去掉 `.lua`（大小写与设备清单一致）。
3. 文件执行完毕返回一张表（或调用方需要的值）。

```lua
-- 伪码：led.lua
灯 = {}
function 灯.打开() ... end
返回 灯

-- 伪码：入口
灯 = 加载("led")
灯.打开()
```

未登记的 `.lua` 即使能在电脑上打开，打进包时也不会带上，设备上加载失败。

不要用平台模块的名字当用户文件名。不要把入口脚本再登记成模块。

个数、名字长度和允许的字符见当前型号的 [资源](../dolua-api/nt26/resources/README.md)。

## 4. 配置分区

开机配置 **不是** Lua 模块，不能 `require("rtu_config")`。

文件在工程 config 分区，烧进去后开机解析，按段写入串口、映射、业务开关等。没写的键保持机内原值。语法和全部段见 [`rtu_config.cfg`](../dolua-api/nt26/api/rtu_config/rtu_config.md)。

改脚、改串口分包、改默认路由，优先改这份配置，而不是在脚本里猜硬件。

---

## 5. 内置文件和其它文件

内置文件系统里的资源（例如界面图片、点阵字库）会进设备 **内部字节/对象存储**，和脚本区抢同一块内部共享配额。小资源可以放这里；大图、字库优先考虑外挂盘。额度见当前型号的资源篇。

其它分区适合放说明、原理图、不需要上设备的材料。勾选下载前先确认工具会不会把它打进内部存储。

---

## 6. 清单

设备上每槽有一份清单，描述：

- 副本 ID、版本、构建号
- 入口是否存在、校验
- 用户模块列表（名字、校验、大小）
- 是否启用、启动延迟等选项

清单本身大约 **8 KB** 上限。工具在打包时生成；一般不必手写设备清单 JSON。例程目录里的 `manifest.json` 是给示例索引和工具看的元数据，和槽里那份清单不是同一份文件。

## 7. 打包与部署

```
工程文件夹
    │ 工具打包（压缩）
    ▼
脚本包 ──传输──► 设备当前这份脚本
                    │
                    ▼
              复位后按新包跑
```

当前版本把设备当成 **一份正在跑的脚本** 来部署即可。双槽切换（写到空闲槽、试运行、失败回旧槽）是底层设计，**产品配置未启用**——内部空间不够同时留两份完整包。日后 **8+8** 或 **CAT4** 版本才可能打开，见 [runtime.md 第 2 节](runtime.md#2-脚本副本a--b-两槽)。

传输路径可以是配套下载、USB 整包、或 AT 按文件写。整包接收还有体积上限，数字见当前型号的资源篇。

不要在回调里改正在跑的自己。换包后通过复位或固件规定的启动路径再生效。
