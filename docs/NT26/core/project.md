# 工程与脚本包

**文档版本** `1.2.0`

DoLua 工程是 **一层文件夹**：里面有入口脚本、可选的用户模块、配置和资源。配套工具把它打成设备能识别的脚本包再烧进去。底层虽按 A/B 两槽设计，**当前版本未启用双槽切换**，见 [runtime.md 第 2 节](runtime.md#2-脚本副本a--b-两槽)。

本篇讲设备侧分区和进设备的路径。侧边栏怎么认工程、五区怎么勾选、LUAPK 怎么生成，见 [工程结构](../../dolua-assisant/工程结构.md)。虚拟机如何跑这份包见 [runtime.md](runtime.md)；配额见 [resources.md](resources.md)。

## 1. 仓库和工程不是同一层

配套工具里的 **Lua workspace**（以及 demo 根）是仓库：下面可以有很多工程，每个工程单独一层目录。

```
仓库根/                          ← 不要把入口脚本摊在这里
    某工程/                      ← 含工程标志文件的这一层才是工程
        入口脚本
        用户模块…
        配置
        工程标志
```

新建必须先创建这一层工程文件夹，再往里面写文件。编辑器如果把仓库根当成工作区打开，相对路径上的 `main.lua` 会变成仓库根上的文件——那不是一份合法工程。

官方可导入例程在文档仓的 `examples/NT26/`，每个子目录就是一份工程。

## 2. 工程分区

工具侧常见五类。名字以工具为准，含义如下。

| 分区 | 典型文件 | 进不进脚本包 |
| --- | --- | --- |
| 主文件 | 入口脚本，几乎总是一份 | 进，作为虚拟机入口 |
| 模块 | 你的 `.lua` | 勾选并登记的才进 |
| 配置 | 开机配置文件 | 进配置通道，开机解析 |
| 内置文件系统 | 图片、字库、清单类资源 | 进内部存储，占共享配额 |
| 其它 | README、不需要上设备的附件 | 默认不上设备；看是否勾选 |

**不要**靠手改工程标志 JSON 来增删分区或勾选。用配套工具或 MCP 提供的工程接口，否则界面和监视器可能把你的改动盖掉。

## 3. 用户模块怎样才能 require 到

三件事必须同时成立：

1. 文件在工程文件夹里，且登记在 **模块** 分区。
2. `require` 的名字 = 文件名去掉 `.lua`（大小写与设备清单一致）。
3. 文件执行完毕返回一张表（或调用方需要的值）。

```lua
-- 伪码：led.lua
灯 = {}
function 灯.打开() ... end
返回 灯

-- 伪码：入口
灯 = 加载("led")
灯.打开()
```

未登记的 `.lua` 即使能在电脑上打开，打进包时也不会带上，设备上加载失败。

不要用平台模块的名字当用户文件名。不要把入口脚本再登记成模块。

个数上限 **35**、名字最长 **31** 字符、允许字母数字与 `.` `_`，见 [resources.md](resources.md)。

## 4. 配置分区

开机配置 **不是** Lua 模块，不能 `require("rtu_config")`。

文件在工程 config 分区，烧进去后开机解析，按段写入串口、映射、业务开关等。没写的键保持机内原值。语法和全部段见 [`rtu_config.cfg`](../api/rtu_config/rtu_config.md)。

改脚、改串口分包、改默认路由，优先改这份配置，而不是在脚本里猜硬件。

---

## 5. 内置文件和其它文件

内置文件系统里的资源（例如界面图片、点阵字库）会进设备 **内部字节/对象存储**，和脚本区抢同一块 220 KB 配额。小资源可以放这里；大图、字库优先考虑外挂盘。

其它分区适合放说明、原理图、不需要上设备的材料。勾选下载前先确认工具会不会把它打进内部存储。

## 6. 清单

设备上每槽有一份清单，描述：

- 副本 ID、版本、构建号
- 入口是否存在、校验
- 用户模块列表（名字、校验、大小）
- 是否启用、启动延迟等选项

清单本身大约 **8 KB** 上限。工具在打包时生成；一般不必手写设备清单 JSON。例程目录里的 `manifest.json` 是给示例索引和工具看的元数据，和槽里那份清单不是同一份文件。

## 7. 打包与部署

```
工程文件夹
    │ 工具打包（压缩）
    ▼
脚本包 ──传输──► 设备当前这份脚本
                    │
                    ▼
              复位后按新包跑
```

当前版本把设备当成 **一份正在跑的脚本** 来部署即可。双槽切换（写到空闲槽、试运行、失败回旧槽）是底层设计，**产品配置未启用**——内部空间不够同时留两份完整包。日后 **8+8** 或 **CAT4** 版本才可能打开，见 [runtime.md 第 2 节](runtime.md#2-脚本副本a--b-两槽)。

传输路径可以是配套下载、USB 整包、或 AT 按文件写。整包接收还有约 260 KB 的闸门，见资源篇。

不要在回调里改正在跑的自己。换包后通过复位或固件规定的启动路径再生效。
