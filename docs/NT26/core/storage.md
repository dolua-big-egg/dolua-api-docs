# 存储怎么分

**文档版本** `1.1.0`

设备上和脚本相关的存储分成两块：**内部共享区**（和脚本源码抢配额）以及 **外挂 Flash**（独立芯片，不进那 220 KB）。选错块，轻则写不下，重则把脚本升级空间吃光。

函数契约见 [`ufs`](../api/module/ufs.md)、[`ublob`](../api/module/ublob.md)、[`lfs`](../api/module/lfs.md)、[`flashdb`](../api/module/flashdb.md)、[`sfud`](../api/module/sfud.md)。本篇只帮你对号入座。

## 1. 先看这张图

```
┌─────────────────────────────────────────────┐
│ 内部 Flash 共享配额（NT26 PRO：220 KB 压缩后） │
│                                             │
│   脚本区（A 槽 + B 槽的入口和用户模块）        │
│   内部对象文件（Lua 值）                      │
│   内部字节文件（原始 string）                 │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│ 外挂 NOR（有芯片才有）                         │
│   文件树（LittleFS）                          │
│   KV / 时序库                                 │
└─────────────────────────────────────────────┘
```

没有外挂芯片时，只能用内部共享区。有芯片时，大文件、历史数据应优先外挂，把 220 KB 留给脚本和少量配置。

## 2. 内部共享区

三家合用，按压缩后占盘核算：

```
脚本落盘 + 对象文件落盘 + 字节文件落盘  ≤  总额
对象/字节还能写多少  =  总额 − 脚本落盘
```

| 事实 | 后果 |
| --- | --- |
| A、B 两槽都计数 | 底层设计如此；**当前未启用切槽**，不要按两份完整包规划。日后 8+8 / CAT4 若打开，升级时才会短暂存在两份 |
| 总额随型号公布 | NT26 PRO 为 220 KB；以设备用量查询为准 |
| 压缩比因内容而异 | 源码字符数 ≠ 占盘字节 |
| 复位不擦内部文件 | 虚拟机没了，文件还在 |

脚本区只放 **要执行的 Lua 源码**。图片、日志、固件片放进来会直接挤压升级空间。

用量查询一次给出「已用、脚本已用、可写上限、总额」这类字段，对象文件接口和字节文件接口看到的是同一块空间的两个视图。

## 3. 内部对象 vs 内部字节

同一块配额，两套用法，**同名互不可见**。

| | 内部对象 | 内部字节 |
| --- | --- | --- |
| 存什么 | 可序列化的 Lua 值（空、布尔、数字、字符串、表） | **只能** 字节串 |
| 读回 | 仍是对象 | 仍是字节，不会帮你解成表 |
| 适合 | 配置、设备状态、短 KV | 日志块、图片、HTTP 正文、固件片 |
| 写入 | 整值覆盖 | 可覆盖，也可分段追加后再整包重写 |
| 单次限制 | 编码 RAM 约 80 KiB，宜短小 | 单文件明文约 256 KiB |
| 表 | 嵌套 10 层、单表 4096 项 | 不负责编表 |

多字段请打成 **一张表一次写入**。拆成很多小对象文件，每次落盘都有压缩记录开销。

不能序列化：函数、用户数据、协程、循环引用。需要存「打开着的脚 / 客户端」时，存能重建它们的参数，不要存句柄。

内部区 **不是** POSIX：没有目录树、没有随便 `open` 的路径、没有和电脑磁盘一样的随意追加语义（字节文件的追加在实现上往往是读出再写回，大文件会再占一份明文 RAM）。

## 4. 外挂 Flash

外挂 NOR 要先按硬件和 SPI 模块选脚、再挂文件系统或 KV。它：

- **不占用** 220 KB 内部配额
- 适合大文件、很多小记录、掉电也要留很久的历史
- 需要芯片、布线和正确的分区；没有芯片时接口会失败

两类常见用法：

| 用法 | 适合 |
| --- | --- |
| 文件树 | 按路径存固件片、CSV、图片；HTTP 也可以直接存到这里 |
| KV / 时序 | 大量键值、带时间戳的采样点 |

同一颗芯片上可以按分区同时用文件树和 KV，见存储类例程里的混合工程。挂载可能是异步的：脚本要等挂载完成再读写，不要在回调里同步挂。

## 5. 网络下载存到哪

| 目标 | 可以吗 |
| --- | --- |
| 内部字节文件 | 可以，注意明文 256 KiB 和共享配额 |
| 内部对象文件 | **不要** 把 HTTP 正文当对象直接存；对象模块不是给二进制流用的 |
| 外挂文件树 | 大文件首选 |
| 脚本区 | 那是入口和用户模块，不是下载盘 |

把大图打进工程「内置文件系统」再下载，效果等于占用内部配额。界面资源很大时，改放外挂或减尺寸。

## 6. 选型

| 需求 | 放哪 |
| --- | --- |
| 运行参数、阈值、一小张状态表 | 内部对象，合并成一张表 |
| 几 KB 的日志块、一张小 JPEG | 内部字节 |
| 几百 KB 的固件、相册、长时间 CSV | 外挂文件树 |
| 海量采样点 | 外挂时序 / KV |
| 要执行的业务代码 | 脚本区（入口 + 用户模块） |
| 开机串口脚位、分包 | 配置分区，不是这三类存储 |

不确定时：短小且跟着脚本走的 → 内部；大、多、可单独擦写的 → 外挂；能执行的代码 → 脚本区。
