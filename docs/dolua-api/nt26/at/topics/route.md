# 路由专栏

**文档版本** `1.0.0`

场景专题：透传里两股数据往哪走。

- **上行**：输入是 **串口**（UART1～3）。MCU 送来的每一包，按该口的 `AT+DTUPSUP` 送到哪些出口。
- **下行**：输入是 **四路通道**（任务 1～4，SOCK 或 MQTT）。网络送来的每一包，按该路的 `AT+DTUPSDN` 送到哪些出口。

路由串怎么写、子通道上限、非法写法见 [路由串手册](../manual/route.md)。`DTUPSUP` / `DTUPSDN` 指令形态见 [透传任务](../manual/rtu.md#6-atdtupsup--atdtupsdn)。本篇按方向把能抄的组合写全。

心跳 / 注册包最后一段 **不是**这套语法，见 [第 8 节](#8-不要和这几件事搞混)。

## 1. 两股数据

上下行是 **两张独立的表**，不会因为配了上行就自动配下行。

```lua
MCU ──UART1/2/3──► AT+DTUPSUP=<口>,"<出口>"  ──► 通道 1～4 / HTTP / 其它 UART / 短信
云端 ──通道 1～4──► AT+DTUPSDN=<路>,"<出口>"  ──► UART / 其它通道 / HTTP / 短信
```

| | 上行 `DTUPSUP` | 下行 `DTUPSDN` |
| --- | --- | --- |
| 输入 | 某一路 **UART**（1～3） | 某一路 **任务通道**（1～4） |
| 指令第一参 | 串口号 | 通道号 |
| 第二参 | 这份串口数据要送到哪 | 这份通道数据要送到哪 |
| 典型出口 | `"1"`、`"1\|2"`、`"1[1:2]"`、`"5[1]"` | `"6[1]"`、`"6[2]"`、`"6[1:2]"`、`"2\|6[1]"` |
| 谁先要起来 | 出口侧 SOCK/MQTT/HTTP 已使能 | 该路 `DTUTASK` 已使能且已连上 |

AT 口（常见 UART1）默认仍解析 `AT+…`。业务 MCU 尽量走 **另一路 UART**，否则二进制会被当成指令。必须共用一口时，配完再用 [AT+RTUPSD](../manual/rtu.md#8-atrtuctl--atrtupsd--atdtumsghead) 把 AT 口锁成透传。

## 2. 出口怎么写（够用即可）

路由串选的是 **出口集合**。一级数字是类别，方括号里才是该类的第几路。

| 写入 | 实际送到 |
| --- | --- |
| `1` | 任务通道 1（SOCK 整包 / MQTT **发布槽 1**） |
| `1[1:2]` | 通道 1 的 MQTT 槽 1 和 2（SOCK 时多写槽也不会拆成两路 TCP） |
| `1\|2` | 通道 1 和通道 2 各一份 |
| `5[1]` | HTTP 通道 1（载荷当请求体；须已 `HTTPURL` 使能） |
| `6[1]` | UART1 |
| `6[2]` | UART2 |
| `6[1:2]` | UART1 和 UART2 各一份 |
| `7[1]` | 短信通道 1 |
| `""` | 合法：不选任何出口，等于不发 |

不写括号时默认子通道 1：`6` 等于 `6[1]`。查询时常把 `6[1]` 回显成 `"6"`，含义没变。

`AT+SOCK=1` 的 `1` 和路由里的 `1` 是同一路业务通道；`AT+UART=1` 的 `1` **不是**路由里的 `1`，UART 要写 `6[1]`。完整表见 [route.md](../manual/route.md)。

## 3. 上行：输入是串口

三路 UART **各有一条**上行表。只改 UART1 不会动 UART2。

```lua
AT+DTUPSUP=<uart_id>,"<路由>"
AT+DTUPSUP=<uart_id>?
```

`<uart_id>` = 1、2、3。

### 3.1 一份数据进一路通道

UART1 → 通道 1（最常见）：

```lua
AT+DTUPSUP=1,"1"
+DTUPSUP: 1,"1"

OK
```

MCU 接 UART2，AT 仍在 UART1：

```lua
AT+DTUPSUP=2,"1"
+DTUPSUP: 2,"1"

OK
```

通道 1 须已 `DTUTASK=1,1,"SOCK"` 或 `"MQTT"`。MQTT 时 `"1"` 只打到**发布槽 1**，该槽主题不能为空。

### 3.2 一份数据进多路通道

同一包复制到通道 1 和 2：

```lua
AT+DTUPSUP=1,"1|2"
+DTUPSUP: 1,"1|2"

OK
```

两路可以一路 SOCK、一路 MQTT（混合任务见 [Socket 专栏](socket.md#5-混合通道) / [MQTT 连接专栏](mqtt.md#5-混合通道)）。

四路全要（出厂演示口径常见）：

```lua
AT+DTUPSUP=1,"1|2|3|4"
```

### 3.3 MQTT：选发布槽

通道 1 是 MQTT，串口数据同时发到槽 1 和槽 2：

```lua
AT+MQTTPUB=1,1,"/device/data",0,0
AT+MQTTPUB=1,2,"/device/alarm",0,0
AT+DTUPSUP=1,"1[1:2]"
+DTUPSUP: 1,"1[1:2]"

OK
```

槽 3、5、8：

```lua
AT+DTUPSUP=1,"1[3:5:8]"
```

路由串最多写到槽 **8**。槽 9、10 只能 `MQTTSYNC` / `MQTTASYNC`，透传走不到。

SOCK 通道写 `1[1:2]` 不会变成两路 TCP，整包仍只进这一路 Socket。

### 3.4 串口数据触发 HTTP

载荷当作该 HTTP 通道的请求体。通道须 POST/PUT 且已使能：

```lua
AT+HTTPURL=1,1,2,"","http://10.0.0.8/api/echo"
AT+DTUPSUP=1,"5[1]"
+DTUPSUP: 1,"5[1]"

OK
```

既上 Socket 又打 HTTP：

```lua
AT+DTUPSUP=1,"1|5[1]"
```

HTTP 第 5 路不要只靠路由串触发（`5[5]` 能存，当前写出不会发），用 `AT+HTTPREQ=5,…`。见 [HTTP 专栏](http.md)。

### 3.5 串口抄到另一路串口或短信

UART2 的数据镜像到 UART3（调试）：

```lua
AT+DTUPSUP=2,"6[3]"
```

不要把某口的上行指回 **自己**（`DTUPSUP=1,"6[1]"`）：等于串口环回，容易打满。需要「网络回包出串口」走的是下行，不是这里。

发短信（号码在 `[sms.N]`）：

```lua
AT+DTUPSUP=1,"7[1]"
```

### 3.6 三路串口各走各的

```lua
AT+DTUPSUP=1,"1"
AT+DTUPSUP=2,"2"
AT+DTUPSUP=3,"1|2"
```

UART1 → 通道 1，UART2 → 通道 2，UART3 → 两路都送。

查询：

```lua
AT+DTUPSUP=1?
+DTUPSUP: 1,"1"

OK
```

## 4. 下行：输入是四路通道

四路任务 **各有一条**下行表。通道 1 的回包不会自动出现在 UART 上，除非这路 `DTUPSDN` 选了 UART。

```lua
AT+DTUPSDN=<channel_id>,"<路由>"
AT+DTUPSDN=<channel_id>?
```

`<channel_id>` = 1、2、3、4，与 `AT+DTUTASK` / `AT+SOCK` / `AT+MQTT` **同一路 N**。输入是该路从网络收到的数据（TCP 流 / MQTT 已订阅主题的载荷）。

### 4.1 通道回包出一路串口

通道 1 → UART1（最常见）：

```lua
AT+DTUPSDN=1,"6[1]"
+DTUPSDN: 1,"6[1]"

OK
```

查询常回 `"6"`，与 `"6[1]"` 同义。

MCU 在 UART2：

```lua
AT+DTUPSDN=1,"6[2]"
+DTUPSDN: 1,"6[2]"

OK
```

### 4.2 同一路回包出多路串口

通道 1 同时给 UART1 和 UART2（一份给 MCU、一份给调试口）：

```lua
AT+DTUPSDN=1,"6[1:2]"
+DTUPSDN: 1,"6[1:2]"

OK
```

### 4.3 四路通道分别出不同串口

```lua
AT+DTUPSDN=1,"6[1]"
AT+DTUPSDN=2,"6[2]"
AT+DTUPSDN=3,"6[1]"
AT+DTUPSDN=4,"6[3]"
```

通道 1、3 都出 UART1 时，两路回包会在同一条串口上交织。调试可 `AT+DTUMSGHEAD=1` 给来源标识，量产再关。

### 4.4 通道回包转到另一路通道

通道 1 收到的数据再转给通道 2（桥接），并抄一份到 UART1：

```lua
AT+DTUPSDN=1,"2|6[1]"
+DTUPSDN: 1,"2|6[1]"

OK
```

通道 2 是 MQTT 时，`"2"` 默认发布槽 1；要槽 1 和 2：

```lua
AT+DTUPSDN=1,"2[1:2]|6[1]"
```

不要配成互相转发死循环（通道 1 下行到 2、通道 2 下行到 1）除非你明确要这么做。

### 4.5 通道回包触发 HTTP 或短信

```lua
AT+DTUPSDN=1,"5[1]"
AT+DTUPSDN=1,"7[1]|6[1]"
```

前者：网络来的包当 HTTP 请求体。后者：既发短信又出 UART1。

### 4.6 查询

```lua
AT+DTUPSDN=1?
+DTUPSDN: 1,"6[1]"

OK
```

## 5. 双向透传怎么配对

「串口 ↔ 云」必须 **上行 + 下行各写一条**。只写 `DTUPSUP` 则云收得到、MCU 看不到回包；只写 `DTUPSDN` 则 MCU 收得到云、串口数据上不去。

### 5.1 UART1 ↔ 通道 1

```lua
AT+DTUPSUP=1,"1"
AT+DTUPSDN=1,"6[1]"
```

### 5.2 UART2 ↔ 通道 1（AT 留在 UART1）

```lua
AT+DTUPSUP=2,"1"
AT+DTUPSDN=1,"6[2]"
```

### 5.3 UART1 ↔ 通道 1 和通道 2（一上两路）

上行同一包复制两路；两路回包都回到 UART1：

```lua
AT+DTUPSUP=1,"1|2"
AT+DTUPSDN=1,"6[1]"
AT+DTUPSDN=2,"6[1]"
```

### 5.4 两路串口各绑一路通道

```lua
AT+DTUPSUP=1,"1"
AT+DTUPSDN=1,"6[1]"
AT+DTUPSUP=2,"2"
AT+DTUPSDN=2,"6[2]"
```

### 5.5 MQTT 多主题

上行打到通道 1 的槽 1、2；下行仍出 UART1（订阅到的载荷不按槽拆出口，整路共用这条 `DTUPSDN`）：

```lua
AT+DTUPSUP=1,"1[1:2]"
AT+DTUPSDN=1,"6[1]"
```

写完后按产品流程复位，等通道起来。联调步骤见 [Socket 专栏](socket.md) / [MQTT 连接专栏](mqtt.md)。

## 6. 混合出口

上行、下行都可以在同一条路由串里用 `|` 并选多类出口。顺序不限，查询回显按通道号 1～7 升序。

UART1 同时：上通道 1、打 HTTP 通道 1、抄到 UART3：

```lua
AT+DTUPSUP=1,"1|5[1]|6[3]"
```

通道 1 下行同时：出 UART1、转到通道 2、发短信 1：

```lua
AT+DTUPSDN=1,"2|6[1]|7[1]"
```

同一类不要写两遍：`1[2]|1[3]` 后一段会被丢掉，只留下 `1[2]`。要槽 2 和 3 写成 `1[2:3]`。

## 7. 关掉某一方向

空串合法，表示这份输入不再转发：

```lua
AT+DTUPSUP=1,""
+DTUPSUP: 1,""

OK

AT+DTUPSDN=1,""
+DTUPSDN: 1,""

OK
```

只关 UART1 上行、其它口和四路下行不受影响。任务仍可连着，只是这条串口不再往网上送。

## 8. 不要和这几件事搞混

| 容易当成路由的 | 实际 |
| --- | --- |
| `AT+DTUHEART` / `AT+DTUREG` 最后一段 | 本路 MQTT **发布槽**列表 `"1\|2"`，没有 `6[1]`，写了也不会出串口 |
| `AT+HTTPCFG` 的 `route` | HTTP **响应**打到哪，不是 `DTUPSUP`。串口触发 HTTP 仍用上行里的 `5[N]` |
| `AT+RTUWRITE="…"` | AT 口主动按路由发一包，**不经过**串口上行表，也不改 `DTUPSUP`/`DTUPSDN` |
| `[lua] print_route` | `uart1` 这种名字，不是 `6[1]` |
| 通道 1 下行到 `1` | 把回包再送进通道 1 自己，通常不是你要的 |

`RTUWRITE` 适合从 AT 口点名出口，例如不经过 UART 直接往通道 1 送：

```lua
AT+RTUWRITE="1",hello
OK
```

这和「UART1 的 `DTUPSUP`」是两条路径。

## 9. 常见失败

| 现象 | 先查 |
| --- | --- |
| 串口有数据，服务器没有 | `DTUPSUP` 是否指向该通道；该路 `DTUTASK` 是否使能；是否把数据打到了 AT 口 |
| 服务器有回包，MCU 没有 | 该路 `DTUPSDN` 是否指向实际接线的 UART（MCU 在 UART2 时不要写成 `6[1]`） |
| MQTT 透传无发布 | 路由子通道对应的发布槽主题是否为空；写了 `1[9]` 会整串非法 |
| HTTP 没被串口触发 | 上行是否写了 `5[1]` 而不是 `1`；该 HTTP 通道是否 POST/PUT 且 `enable=1` |
| 配了上行以为能收 | 下行是另一条 `DTUPSDN`，不会自动互指 |
| 查询变成 `"6"` | 就是 `"6[1]"` |
| `"error route_str"` | 括号不成对、通道号不是 1～7、子通道越界 |
| AT 口突然不认指令 | 业务数据和 AT 抢同一口，或开了 `RTUPSD` |

语法非法与失败码见 [route.md 第 8 节](../manual/route.md#8-非法与失败)。解析成功只表示串合法，不保证对端已连接。
