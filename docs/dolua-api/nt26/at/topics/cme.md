# CME ERROR 专栏

**文档版本** `1.0.0`

一条 `+CME ERROR: <n>` 背后是两个码段，数字落在哪段，决定这条失败是 AT 引擎自己报的，还是业务指令报的：

- **段 1**：`0`～`8`，AT 引擎自己（`atlite` 的 `at_error_type_t`，起始值 **0**）。指令没注册、参数个数或类型不对，都走这里。
- **段 2**：`101`～`156`，模组自定义业务码（`at_cme_error_t`，起始值 **101**）。SIM / 驻网 / 定位 / DNS / IO 这些业务失败走这里。

两套表都从**同一个 `+CME ERROR:` 前缀**出去，只看前缀分不出是谁报的，必须先看数字。段 2 的完整表可用 `AT+CMEERR` 在机器上打出来。

段 1 / 段 2 的判断与逐码含义看 [第 4 节](#4-段-1at-引擎08)、[第 5 节](#5-段-2自定义业务101156)；行格式与和其它失败风格的关系看 [convention.md](../manual/convention.md) 第 3 节。

## 1. 两个段怎么分

只看 `+CME ERROR:` 后面的数字：

| 数字 | 谁报的 | 典型原因 | 表在哪 |
| --- | --- | --- | --- |
| `0`～`8` | AT 引擎（指令框架） | 指令名没注册、参数个数/类型/范围不对 | 本篇 [第 4 节](#4-段-1at-引擎08) |
| `101`～`156` | 业务指令回调（模组自定义） | SIM、驻网、定位、DNS、IO、OTA 等业务失败 | 本篇 [第 5 节](#5-段-2自定义业务101156)，机器上打 `AT+CMEERR` |
| 其它 | 别处（例如 APN 回协议栈负数） | 见 [第 8 节](#8-不要和这几件事搞混) | 该指令所属篇 |

段 1 与段 2 都从 `atlite` 那层出来，但**不是同一张表**：段 1 是 `at_error_type_t`（从 `0` 起算，实际只用 `1`～`8`），段 2 是 `at_cme_error_t`（从 `101` 起算）。源码里两张表分别定义，只是共用同一个失败行前缀。

段 1 的数字小、段 2 从三位数开始，所以「个位数 / 三位数」是最快的粗分法。三位数目前只定义到 `156`，再大就没有含义了。

## 2. 行格式

两个段共用同一种行格式，MCU 侧按 `\r\n` 切行即可：

```lua
\r\n+CME ERROR: <n>\r\n\r\n
```

失败行**不带** `OK`，之后就是本条结束。少数指令是例外，在 `+CME ERROR` 之后仍跟 `OK`，以该指令所属篇为准（手册里已点名的有 `AT+NTP`、`AT+SIMINFO`）。

## 3. 段和入口的关系

同一套 `+CME ERROR` 出现在所有 AT 入口，不只串口：

| 入口 | 说明 |
| --- | --- |
| UART1～3 | 常见 AT 口，段 1 / 2 都可能出现 |
| USB VCOM0 | 与串口同一条解析路径 |
| 四路通道（SOCK / MQTT） | 收到的 AT 由同一引擎解析，失败同样回 `+CME ERROR` |
| Lua `virat.exec` | 虚拟 AT 通道；返回值里带上这段文本 |
| OTA / UPDATE 通道 | 同一引擎，响应走独立缓冲 |

所以「串口上能收到的失败行」和「Socket 里发 AT 收到的失败行」是同一套数字，不要按入口分别记表。

Socket / MQTT **指令自己**的失败走短 reason `"error <reason>"`，不是 CME；见 [第 8 节](#8-不要和这几件事搞混)。

## 4. 段 1：AT 引擎（0～8）

指令还没进业务回调就被拦下时报这个段。`0` 是「无错误」占位，**不会**出现在线上；实际会看到的是 `1`～`8`。

| 码 | 含义 | 什么情况会看到 |
| --- | --- | --- |
| 0 | 无错误 | 占位值，不上线 |
| 1 | 指令未注册 | 指令名不在本机注册表里（名字拼错、该指令没编进本固件） |
| 2 | 规则解析失败 | 指令自己的参数规则串非法；规则是固件内置的，正常不会出现 |
| 3 | 参数分割失败 | 引号不成对、逗号切不干净 |
| 4 | 参数数量不匹配 | 必填参数少写，或多写了一整段 |
| 5 | 参数验证失败 | 类型不对（该数字给了字符串）、越界（通道号、长度） |
| 6 | 内存分配失败 | 解析期间申请缓冲失败，通常伴随堆紧张 |
| 7 | 指令类型不支持 | 该指令只支持某一种形态，却按另一种发了 |
| 8 | 查询通道多参数 | 查询通道形态只能带一个参数，多写了 |

要点：

1. 段 1 只看**指令名与参数形态**，不看业务。业务值本身非法（例如通道号超范围）会由业务回调报段 2 的 `105`，不是这里的 `5`。
2. `1`（未注册）最容易被当成「指令坏了」。先确认这一篇手册里有没有这条指令，再确认机型固件是否包含该业务。
3. `7` 的典型来源是无加号形态与标准形态混用：`ATI` 一类只走无加号，`AT+XXX` 一类只走标准。

## 5. 段 2：自定义业务（101～156）

业务回调自己报的失败。这张表就是 `AT+CMEERR` 打出来的机内表，新增码时以机器输出为准。

表里是本固件**已定义**的全部业务码；单条指令只会回其中一小部分，具体以该指令所属篇的「错误一览」为准。

### 5.1 参数与文件（104～112、123、124）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 104 | 未知的 key | `*CFG` 类指令的 key 拼错或本机不支持 |
| 105 | 无效参数 | 最常遇到：类型不对、越界、枚举不在取值里 |
| 106 | 文件读取失败 | 读配置 / 文件系统 |
| 107 | 文件写入失败 | 落盘失败 |
| 108 | 参数长度超过限制 | 字符串太长 |
| 109 | 路由转换失败 | 路由串语法非法，见 [路由串手册](../manual/route.md) |
| 110 | 该指令不支持这个通道 | 该指令在别的通道才有意义 |
| 111 | 文件读取超时 | |
| 112 | 内存分配失败 | |
| 123 | 时间字符串解析失败 | 时间类入参格式不对 |
| 124 | 参数长度不足 | 必填内容为空或太短 |

### 5.2 SIM 与标识（113～122、131、143～150）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 113 | SIM 信息 HTTP 请求失败 | `AT+SIMINFO` 拉平台的网络段失败 |
| 114 | SIM 信息 JSON 解析失败 | 平台返回体结构异常 |
| 115 | SIM 信息请求超时 | |
| 116 | SIM 信息 ICCID 获取失败 | |
| 117 | SIM 信息 IMSI 获取失败 | |
| 118 | SIM 信息 IMEI 获取失败 | |
| 119 | SIM 信息 CSQ 获取失败 | |
| 120 | SIM 信息 CFUN 获取失败 | |
| 121 | SIM 信息 SIM ID 获取失败 | 读卡槽/卡标识失败 |
| 122 | SIM 信息 SIM ID 设置失败 | 切卡、设槽失败 |
| 131 | ICCID 获取失败 | 未归到更细码时的通用失败 |
| 143 | SIM 未插入 | 优先怀疑卡座与卡 |
| 144 | SIM / 协议栈未上电或未就绪 | 例如 `AT+CFUN=0` 之后读卡信息 |
| 145 | SIM 忙 | 稍后重试 |
| 146 | SIM 同步查询超时 | |
| 147 | SIM 响应异常 | |
| 148 | SIM 相关操作不支持 | |
| 149 | IMSI 获取失败 | 未归类时的通用失败 |
| 150 | IMEI 获取失败 | 未归类时的通用失败 |

`143` / `144` 是现场最值得先分的两条：卡没插 vs 卡插了但协议栈没起。`AT+CFUN=0` 之后读 ICCID / IMSI 常见 `144`。

### 5.3 驻网与定位（139～141、151 及 130）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 130 | LBS 获取失败 | 基站定位整体失败 |
| 139 | Wi-Fi 扫描超时 | `AT+WIFISCAN` 等不到结果 |
| 140 | 小区信息未就绪 | `AT+MCC` / `AT+MNC` / `AT+CGI` 在没驻网时 |
| 141 | 复位监控分钟超范围 | `mrst.*` 分钟不是 `0` 也不是 `1`～`1440` |
| 151 | Wi-Fi 扫描失败 | 扫描本身失败 |

### 5.4 DNS 与 NTP（101～103、152～156）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 101 | NTP 请求超时 | `AT+NTP` 等不到服务器（该条失败后仍跟 `OK`） |
| 102 | NTP 失败 | |
| 103 | NTP 设置失败 | |
| 152 | DNS 服务器查询失败 | |
| 153 | DNS 服务器设置失败 | |
| 154 | 域名解析失败 | 服务器地址不可解析 |
| 155 | DNS 缓存清除失败 | |
| 156 | DNS CID 状态查询失败 | |

### 5.5 IO 与 OTA（125～129、132～138）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 125 | IO 未初始化 | 该脚还没 `IOCFG` / `IOSET` 过 |
| 126 | IO 模式未对应 | 当前模式不允许这个操作 |
| 127 | IO 不支持 | 该脚不在当前固件落盘的外设表里 |
| 128 | 不支持的 IO 状态 | |
| 129 | OTA 版本无变化 | `AT+OTA` 给的版本与当前相同 |
| 132 | MCU OTA 下载失败 | `AT+MCUOTA` 分片下载失败 |
| 133 | OTA 不允许跨越大版本号升级 | |
| 134 | 不支持的 IO 模式 | |
| 135 | IO 参数无效 | |
| 136 | IO 任务正在运行 | 上一件没结束 |
| 137 | IO 操作失败 | |
| 138 | ADC 读取失败 | `AT+ADC` 取不到值 |

`125` / `126` / `127` 三条最容易混：**没配过**是 125，**配了但模式不对**是 126，**脚本身不支持**是 127。脚位清单见 [硬件落盘](../../hardware/pro.md#41-gpio)。

### 5.6 诊断（142）

| 码 | 含义 | 常见触发 |
| --- | --- | --- |
| 142 | `mrst.cron` 表达式格式非法 | `AT+DEVICECFG="mrst.cron",…` 里的 cron 写法不合法 |

## 6. 用 AT+CMEERR 现场对表

段 2 的表在机器里，可直接打出来，比翻文档快：

```lua
AT+CMEERR
```

```lua
+CMEERR:
101,"NTP请求超时"
102,"NTP失败"
...
156,"DNS CID状态查询失败"

OK
```

```lua
AT+CMEERR=?
```

```lua
+CMEERR: query all custom +CME ERROR codes (id,"comment" per line)

OK
```

`AT+CMEERR?` 与不带参数等价。这条指令本身失败只回 `ERROR`，不用 `+CME ERROR`。

段 1 **不在**这张表里：`AT+CMEERR` 只列段 2。

## 7. 常见失败

| 现象 | 先查 |
| --- | --- |
| 收到个位数（例如 `+CME ERROR: 1`） | 指令名拼写；该指令是否在手册与当前固件里 |
| 收到 `5` 又觉得参数没错 | 段 1 看的是**形态**；取值范围类错误由业务报段 2 的 `105` |
| 收到 `105` 查文档查不到细节 | 篇内「错误一览」列的是本指令会回的码，`105` 只表示参数被业务判非法 |
| 收到 `144` | 先看是不是刚 `AT+CFUN=0`；再看卡座与协议栈状态，与 `143` 区分 |
| 收到三位数却查不到 | 段 2 只到 `156`，`157`～`999` 目前没有定义 |
| 失败行后面还跟 `OK` | 少数指令如此（如 `AT+NTP`、`AT+SIMINFO`），以该篇为准 |
| 通道指令报 `110` | 该指令不支持当前入口通道，换通道或用对应入口 |

## 8. 不要和这几件事搞混

| 容易混 | 实际 |
| --- | --- |
| `+CME ERROR` 与短 reason | 短 reason 是 `+<CMD>: "error <reason>"` 再 `ERROR`，**不是** CME；各指令用哪一种见各篇「错误一览」 |
| 段 1 与标准 3GPP CME | 数字 1～8 在本机是 AT 引擎码，不是 3GPP 的 `+CME ERROR` 文本码表 |
| APN / APNAUTH 的失败 | 会回协议栈**底层数字**（常见负数，如 `-1`～`-15`、`-127`），不是自定义表里的码 |
| `+CMD` 后面的数字 | 短信发送类 `+CMD: <n>` 是**发送结果码**（`0` 成功），不是 CME |
| `+LOG: 0` / `+PLOG: 0` + `ERROR` | 日志类指令的失败形态，不是 CME |
| `AT+SIMINFO` 失败仍 `OK` | 形态特殊，见该篇 |
| http 专栏里的 TLS 失败 | 走短 reason，不是 CME |

段 2 的表在机器里，别按记忆背；段 1 只有 8 条，背下来比查快。
