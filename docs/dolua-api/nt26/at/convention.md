**文档版本** `1.1.0`

## 1. 行格式

| 项 | 约定 |
| --- | --- |
| 命令结束 | 每条命令以 `<CR><LF>`（`\r\n`）结束。下文示例省略行结束符 |
| 大小写 | 命令名大小写不敏感；参数里的 `key`、主机名按原文保存 |
| 字符串 | 主机、key、路径建议加双引号，例如 `"tcp_host"`、`"10.0.0.8"` |
| 数值 | 十进制整数，不要带符号、不要带小数（电压类指令会单独说明浮点） |
| 尾部裸数据 | `<payload>` 为 **TAILRAW**：最后一个逗号之后到行结束之前的**原始字节**，不做 HEX 文本解码。可含 `0x00`，也可是普通 ASCII |

测试命令（`AT+XXX=?`）返回该指令的取值范围与写法，以 `OK` 结束。

## 2. 命令形态

| 形态 | 写法 | 说明 |
| --- | --- | --- |
| 测试 | `AT+XXX=?` | 多数业务指令支持 |
| 无参查询 | `AT+XXX` 或 `AT+XXX?` | 标识类常用；**Socket / MQTT 通道类多数不支持无参查询** |
| 按通道查询 | `AT+XXX=<id>?` | 多通道指令的标准查法 |
| 按 key 查询 | `AT+XXX=<id>,"<key>"`（无第三参） | 配置类 |
| 设置 | `AT+XXX=<id>,…` | 写入持久化或立刻执行，以该篇为准 |
| 基础命令 | `AT`、`ATI` | 没有 `+` |

没有写「支持无参查询」的指令，不要写 `AT+XXX?`。

## 3. 成功与失败

业务指令有两种失败风格，**以该篇该条为准**，不要混用。

### 3.1 短 reason（Socket / MQTT / UART / 多数配置）

成功：

```lua
<CR><LF>+<CMD>: <字段…><CR><LF>
<CR><LF>OK<CR><LF>
```

失败：

```lua
<CR><LF>+<CMD>: "error <reason>"<CR><LF>
<CR><LF>ERROR<CR><LF>
```

`<reason>` 是短英文词（`param`、`id`、`save`…），各篇「错误一览」列全。

部分发送类指令带 `rsp=0`：**成功、失败都不回** `+CMD` / `OK` / `ERROR`。

### 3.2 `+CME ERROR`（标识 / 驻网 / 定位 / 部分诊断）

```lua
<CR><LF>+CME ERROR: <n><CR><LF>
```

`<n>` 是自定义数字码，见 [第 6 节](#6-自定义-cme-error)。现场可用 `AT+CMEERR` 打出机内对照表。

少数指令（如 `AT+SIMINFO` 失败）在 `+CME ERROR` 之后仍跟 `OK`，以该篇为准。

## 4. 通道编号

换入口不换编号。和 [`rtu_config.cfg`](../api/rtu_config/rtu_config.md#7-通道编号对照) 同一套：

| 业务 | 编号 | 说明 |
| --- | --- | --- |
| Socket / MQTT / RTU 任务 / 通道指示 IO | 1～4 | **同一路** N |
| HTTP | 1～5 | 另一套，不要和上面的 N 当成一路 |
| SSL 证书组 | 1～3 | 被 MQTT / HTTP 的 `ssl_id` 引用 |
| UART | 1～3 | 对应硬件 UART1～3 |
| 短信通道 | 1～10 | `[sms.N]` |
| GPIO（AT `IO*`） | 0～38 | 与配置文件 `[io.N]` 的 **1-based** 脚号差 1：`[io.1]` = AT id `0` |

能 `gpio.open` 的脚不是 0～38 全开，见 [硬件落盘](../hardware/pro.md#41-gpio) 与 [gpio API](../api/peripherals/gpio.md)。

路由串（`1|6[1]` 这种）用的是另一套 **1～7 出口号**：`1`～`4` 才是上表的业务通道；HTTP / UART / 短信的业务编号写在方括号里。见 [route.md](route.md)。

## 5. 与配置文件 / Lua

| 入口 | 做什么 |
| --- | --- |
| 本手册 AT | 改持久化配置，或立刻执行查询/发送 |
| `rtu_config.cfg` | 同一套 key，开机/加载时写入 |
| Lua `require("rtu")` / `tcp` / `mqtt` … | 读的是落盘后的通道，不是另一套编号 |

**写配置的指令默认不拆已经建立的连接。** 正在跑的通道仍用启动时读到的值。要让新主机/端口/保活生效：停通道再启、或按产品流程重新加载配置 / 复位。该篇若写「立刻改 runtime」，以该篇为准。

## 7. 本手册不收录

| 类别 | 例子 | 原因 |
| --- | --- | --- |
| 产测 | 全管脚扫描、深睡电流、射频校准、写号/锁号、产线波特率 | 产线专用，正式产品不要发 |
| 解析自测 | `RAWTEST` / `TAILRAWTEST` / `TEST` | 引擎自测 |
| 已废弃入口 | 旧 YMODEM `DOWNLOAD` | 默认不编译 |
