# Dolua 工程结构

本文说明 **一个 Dolua 工程包含什么**、**磁盘上必须长什么样**，以及 **LUAPK** 和工程之间的关系。侧边栏「工程目录 / 工程文件」就是按这套规则工作的。

---

## 1. 一个工程是什么

一个 Dolua 工程 = **一层文件夹**，并且这一层里有工程描述文件：

```
doiot_lua_project.luaproj
```

插件**只认这个文件**来判定「这里是不是工程」。旧名 `.luaproj`、`.doiot-lua-project.json` 打开时会迁成上面这个名字。

工程里的脚本、配置、资源都放在这个文件夹里（同级或往下的子目录）。路径一律相对描述文件所在目录，不能用 `..`，也不能用绝对路径。

Lua workspace / demo 根是**工程仓库**，下面可以有很多个工程。新建时必须先建一层工程文件夹，例如：

```
workspace/hello/main.lua          ← 正确
workspace/main.lua                ← 错误：不要把入口摊在仓库根
```

---

## 2. 工程里有哪些东西

侧边栏下半「工程文件」把磁盘上的文件分成五区。分区登记写在描述文件里；**没登记进任何分区的文件，一律进「其他文件」。**

### 2.1 主文件

设备入口脚本，**只能有 1 个**，几乎总是 `main.lua`。  
设备启动后从这里开始跑。打包、下载时主文件必须在。

### 2.2 模块

可随工程下载到设备的 Lua 模块（`.lua`）。  
文件名去掉 `.lua` 就是 `require("…")` 的名字。未登记进模块区的 `.lua` **打不进包，设备上也 `require` 不到**。

平台预加载模块（`gpio`、`rt`、`mqtt` 等）没有对应的用户 `.lua`，不要在工程里再放一份同名文件去覆盖。

### 2.3 配置文件

设备 RTU 配置，常见如 `rtu_config.cfg`。可以有多个，但**烧录时只带当前选中的那一份**（单选）。  
烧录时以固定指令名 `_rtu_config_.cmd` 写入设备。

### 2.4 内置文件系统（可选）

要把文件直接烧进设备**内置文件系统**时，归到这一区。后缀不限（图、json、文本都可以）。

每个文件还要选存储位置：

| 位置 | 用途 |
|------|------|
| `ufs` | 可序列化的 Lua 值（配置表等） |
| `blob` | 只存二进制 / 字符串 |

未勾选、或还没选存储位置的内置文件，**不会打进 LUAPK，也不会烧录**。

### 2.5 其他文件

只是放在工程目录里、尚未归类的文件。  
它们会出现在侧边栏，方便你改分区，但**默认不参与勾选下载，也不打进 LUAPK，不烧录到设备**。需要烧录时，把它移到主文件 / 模块 / 配置 / 内置文件系统对应分区。

工程描述文件本身**不会**出现在「其他文件」里，扫描时会跳过。

设备侧这份包怎么跑、内部配额、双槽是否启用，见 [NT26 核心 · 工程与脚本包](../nt26/core/project.md)，不要和本篇的「侧边栏五区」混成一件事。

### 2.6 工程描述文件

`doiot_lua_project.luaproj` 是工程身份和分区账本，记录例如：

- 显示名、设备型号、软件版本等工程信息
- 主文件、模块列表、配置列表与当前选中配置
- 内置文件列表及每个文件的 `ufs` / `blob`
- 勾选下载列表 `checked`

**不要手改这份 JSON 来改分区或勾选。** 请用侧边栏或 MCP 工具（`doiot_classify_files`、`doiot_set_checked` 等），否则界面可能和磁盘不同步。

## 3. 强制结构：文件夹 + 描述文件 + 扫描截断

### 3.1 根目录长什么样

新建工程时，工程文件夹根上至少会有：

```
hello/                          ← 工程根 = 含 luaproj 的那一层
  doiot_lua_project.luaproj     ← 工程描述（判定工程的唯一标志）
  main.lua                      ← 默认主文件
  rtu_config.cfg                ← 默认配置（可选，可再生成）
```

之后你可以加子文件夹，例如 `utils/helper.lua`，相对路径仍从工程根算起。

### 3.2 判定始终跟着描述文件走

- 某目录下**有** `doiot_lua_project.luaproj`（或打开时迁过来的旧名）→ 这一层就是一个工程。
- **没有**这份文件 → 只是普通文件夹，不会当成工程打开、也不会按五区管理。
- 删掉描述文件（「删除工程描述文件」）→ 源码还在，但不再是工程；侧边栏会把它当成普通目录。

分区、勾选、选中配置都以描述文件为准，而不是「磁盘上有个 `.lua` 就算模块」。

### 3.3 识别会截断

扫描 workspace / demo 时：

1. 从上往下走文件夹树。
2. **一旦某层出现工程描述文件，这一层就记成一个工程，不再进入它的子目录继续找工程。**
3. 因此工程内部即使再放子文件夹，也不会被扫成「嵌套工程」。若在已有子工程的目录上再写一份描述文件，扫描会停在这一层，下面的子工程在目录树里不再单独出现。

可以把它理解成：描述文件是树的「叶子工程节点」，碰到就截断。

## 4. LUAPK

**LUAPK**（Lua Update Package，`.luapk`）是由 **当前 Dolua 工程生成的、可以直接烧到设备上的打包固件**。

它不是工程文件夹的拷贝，而是按当前工程打好的可烧录包：主文件、模块、当前选中的配置，以及已勾选且选了存储位置的内置文件。其他文件不进包。

### 4.1 所有下发通道都先生成 LUAPK

无论走哪条路，插件都是 **先根据工程打出一份 LUAPK，再传输**：

| 通道 | 做什么 |
|------|--------|
| 串口 / USB 下载脚本 | 生成 LUAPK → 经当前下载口发给设备 |
| 上传到云端 | 生成 LUAPK → 再上传 |
| 导出到本地 | 生成 LUAPK → 写成 `工程名-版本.luapk` 文件 |

也就是说：设备拿到的始终是 LUAPK，而不是零散的工程文件夹。

### 4.2 用 LUAPK 还原工程

`.luapk` 可以再解回工程：

- 把 `.luapk` **拖进侧边栏工程目录**（workspace / demo）
- 或使用「导入 LUAPK」

插件会解码包内容，在目标目录下写出脚本、配置、内置文件，并生成工程描述文件，然后当成普通 Dolua 工程打开。适合备份、拷贝、以及把已打包固件再改回可编辑工程。

## 5. 对照一览

| 内容 | 在工程里 | 进 LUAPK / 烧录 |
|------|----------|-----------------|
| 主文件 | 必须 1 个 | 是 |
| 模块 | 按需 | 是（已归入模块区的 `.lua`） |
| 配置文件 | 可多个 | 仅当前选中的那一份 |
| 内置文件系统 | 可选 | 已勾选且已选 `ufs` / `blob` 的文件 |
| 其他文件 | 仅占目录 | **否** |
| `doiot_lua_project.luaproj` | 必须 | 否 |
