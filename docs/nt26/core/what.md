# 什么是 DoLua

**文档版本** `1.1.0`

DoLua 是成都度云未来科技有限公司模组上的 **设备端 Lua 运行时**：用一份脚本工程驱动外设、网络、存储和系统能力。当前公开型号是 **NT26**（含 NT26 PRO）。

它不是电脑上的 Lua 解释器，也不是 LuatOS / Air800 / NodeMCU / OpenWrt 那一套。语言内核是 **Lua 5.5**；标准库之外的能力全部来自平台预加载模块。

```lua
-- 伪码：一份工程在概念上长这样
入口脚本:
    打开 指示灯
    循环:
        翻转 指示灯
        让出 一段时间
```

真正怎么写、参数叫什么，见各模块 API 和 [入门示例](../../../examples/nt26/started)。

## 1. 一句话

一台设备、**一个脚本虚拟机**、协作式多任务。你写的是业务：闪灯、采数、上报、存盘。驻网、协议栈、看门狗、AT 通道由固件其它部分负责，脚本通过模块去用它们，而不是去实现它们。

---

## 2. 它在整机里的位置

```
┌─────────────────────────────────────────────────────────┐
│  你的工程                                                │
│  入口脚本 + 用户模块 + 配置 + 内置资源                     │
└────────────────────────────┬────────────────────────────┘
                             │ 烧录 / 升级
┌────────────────────────────▼────────────────────────────┐
│  DoLua 运行时                                            │
│  虚拟机 · 调度循环 · 平台模块                             │
└──────────────┬───────────────────────────┬──────────────┘
               │                           │
               ▼                           ▼
┌──────────────────────┐       ┌──────────────────────┐
│ 外设 / 网络 / 存储     │       │ 驻网、AT、系统监控     │
│ 由模块接到脚本         │       │ 与脚本并行的其它工作   │
└──────────────────────┘       └──────────────────────┘
```

| 层 | 职责 | 脚本要不要管 |
| --- | --- | --- |
| 工程 | 业务逻辑、用户模块、配置、资源文件 | 要 |
| 运行时 | 编译入口、调度协程、派发事件、限制堆和名额 | 遵守规则即可 |
| 固件其它部分 | 蜂窝、USB、AT、喂狗、电源档 | 通过模块使用，不要自行复刻 |

脚本跑在 **一条引擎线程** 里。蜂窝协议、AT 解析等可以在其它线程继续工作。所以「Lua 正在 delay」不等于整机死机；但若你把引擎线程按停（见 [消息和调度](schedule.md)），脚本侧的任务和回调会一起停。

## 3. 语言与标准库

语言是 **Lua 5.5**。语法、table、闭包、协程语义与标准 Lua 一致。

当前固件打开的标准库：

| 有 | 没有 |
| --- | --- |
| 基本库、`package`（因而可以 `require`）、`coroutine`、`string`、`table`、`math`、`utf8`、`debug` | `io`、`os` |

没有 `io` / `os` 是刻意的：设备上没有 POSIX 文件和进程模型。内部短对象走内部存储模块，大文件走字节存储或外挂盘，时间与复位走系统模块。不要写 `io.open`、`os.execute` 去「试一下」。

`print` 是语言内置，在本平台被接到模块串口（默认业务 UART），**不是**电脑终端。带级别和调用点的输出走日志模块，可以和 `print` 走不同口。

## 4. 能力从哪来

两类模块，都用 `require("名字")`，来源完全不同。

### 4.1 平台预加载模块

固件已经准备好：GPIO、UART、MQTT、调度、日志、内部存储……第一次 `require` 时才装进虚拟机（少数启动即用的会提前装上）。

- **没有**对应的用户 `.lua` 文件。
- 不要在工程里放同名 `.lua` 去覆盖。
- 清单以 [API 索引](../api/README.md) 当前列出的为准，不要凭其它模组手册发明名字。

### 4.2 用户模块

工程里你自己写的 `.lua`。文件名去掉后缀就是 `require` 名，文件末尾返回一张表。必须登记进工程的模块分区，未登记的打不进包，设备上 `require` 不到。

```lua
-- 伪码：用户模块
模块 = {
    打开灯 = function() ... end,
    点亮  = function() ... end,
}
返回 模块
```

两类模块共享同一个 `require` 名字空间。用户模块不要起和平台模块相同的名字。

数量、文件名规则、单文件上限见 [可用资源](resources.md) 与 [工程与脚本包](project.md)。

## 5. 一份工程有什么

配套工具里一份工程通常包含：

| 分区 | 典型内容 | 到设备上做什么 |
| --- | --- | --- |
| 主文件 | 几乎总是入口脚本 | 虚拟机启动后跑的那一份 |
| 模块 | 你的 `.lua` | 按需 `require` |
| 配置 | 常见一份开机配置 | 开机解析，写入机内业务配置；**不是** `require` |
| 内置文件系统 | 图片、字库、清单类资源 | 进内部存储，占共享配额 |
| 其它 | 说明、不打包的附件 | 看工具是否勾选 |

工程是 **仓库里的一层文件夹**，不是仓库根摊一份入口脚本。细节见 [工程与脚本包](project.md)。

## 6. 和 AT 的关系

固件同时提供应用 AT（标识、驻网、Socket、脚本部署等）。DoLua 与 AT 操作的是同一台设备上的能力，但脚本侧优先走 Lua 模块。

| 需求 | 倾向 |
| --- | --- |
| 日常业务：灯、串口、MQTT、存配置 | Lua 模块 |
| 产线烧录、查当前脚本 | 配套工具或 [脚本 AT](../at/script.md) |
| 模块文档里没有、且书面指定的原厂补充 | 虚拟 AT 通道（限制很多，先读对应 API） |

能用模块办的事，不必绕一圈发 AT。脚本部署与 Lua 侧「当前这份脚本」查询是同一套包。A/B 双槽是底层设计，**当前配置未启用切换**，见 [runtime.md](runtime.md)。

## 7. 和别的 Lua 不是一套

| 容易当成的 | 实际 |
| --- | --- |
| 电脑 / Node / 浏览器里的 Lua | 单虚拟机、`print` 出 UART、没有 POSIX |
| LuatOS、`sys.wait`、`sys.publish` | 另一家运行时，API 不能用 |
| NodeMCU / OpenWrt Lua | 文件系统、进程、包管理都不同 |
| 标准 Lua 的 `io` / `os` | 本平台未打开 |
| 「硬件中断里跑 Lua」 | 回调在调度循环里执行，见 [schedule.md](schedule.md) |

脚位也不要靠焊盘名或记忆去猜。先看 [硬件脚位](../hardware/README.md)，再打开当前产品那一篇；脚本怎么打开脚仍看对应外设 API。
