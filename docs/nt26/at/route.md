#  路由串

**文档版本** `1.0.1`

这不是一条 `AT+…` 指令。它是若干 AT 参数共用的**字符串语法**，用来写「这一包数据要送到哪些出口」。Lua `rtu.write`、配置文件里的同类字段，和本篇是**同一套写法、同一套编号**。

行格式、失败风格见 [convention.md](convention.md)。各指令怎么把路由串嵌进参数（要不要引号、非法时回短 reason 还是 `+CME ERROR: 109`）以该篇为准。

`[lua] print_route` / `[lua] log_route` **不是**本篇语法，那些是 `uart1` / `uart2` / `uart3` / `usb_at`。[`[log] output`](../api/rtu_config/rtu_config.md#16-log) 仍是整数 `0`～`4`。

## 1. 定位

路由串描述的是 **出口集合**：一级数字选「哪一类口」，方括号里的数字再选「这一类里的哪几路」。写出时对选中的每一路各送同一份数据。

两套编号不要混：

| 写法 | 实际送到 |
| --- | --- |
| `AT+SOCK=1` / `AT+MQTT=1` 的通道 `1` | 业务通道 1 |
| 路由串里的 `1` | **同一路**业务通道 1 |
| `AT+HTTPURL=1` 的通道 `1` | HTTP 通道 1 |
| 路由串里的 `5[1]` | **才是** HTTP 通道 1；写 `1` 不会进 HTTP |
| `AT+UART=1` 的口 `1` | UART1 |
| 路由串里的 `6[1]` | **才是** UART1；写 `6` 而不写括号时默认也是 UART1 |

## 2. 写法

```lua
<通道>
<通道>[<子1>:<子2>:<子3>]
<通道>|<通道>
<通道>[<子…>]|<通道>[<子…>]
```

| 符号 | 作用 |
| --- | --- |
| 通道号 | 十进制整数 **1～7**，见 [第 3 节](#3-通道号一览) |
| `\|` | 并选多类出口。顺序不限，查询回显按 1～7 升序 |
| `[…]` | 该类里的子通道列表，从 **1** 计 |
| `:` | 子通道之间的分隔 |
| 不写 `[]` | 默认只选该类的子通道 **1** |
| 空串 `""` | 合法：不选任何出口。写出等于不发 |

空白（空格 / Tab）可写在数字和分隔符两侧，解析时跳过。通道号、子通道号必须是十进制正整数，不要写名字。

括号必须成对：`1[2`、`1]2`、`]1[` 整串非法。同一通道写两次，**后出现的整段忽略**（含后写的子通道）。例如 `1[2]|1[3]` 只留下通道 1 的子通道 2。

子通道超出该通道上限，整串非法。上限见 [第 4 节](#4-子通道一览)。

## 3. 通道号一览

一级数字 **只表示出口类别**。HTTP / UART / 短信的业务编号在方括号里，不在一级。

| 通道号 | 指向 | 子通道范围 | 不写 `[]` 时默认 |
| --- | --- | --- | --- |
| `1` | RTU 任务 / Socket / MQTT **通道 1**（与 `AT+SOCK=1` / `AT+MQTT=1` / `AT+DTUTASK=1` 同一路） | 1～8 | 子通道 1 |
| `2` | 同上，**通道 2** | 1～8 | 子通道 1 |
| `3` | 同上，**通道 3** | 1～8 | 子通道 1 |
| `4` | 同上，**通道 4** | 1～8 | 子通道 1 |
| `5` | HTTP（一类） | 1～5 | HTTP 通道 1 |
| `6` | UART（一类） | 1～3 | UART1 |
| `7` | 短信（一类） | 1～10 | 短信通道 1 |

没有通道 `8` 及以上。写 `0`、负数、非数字都会整串失败。

任务 1～4 当时配成 SOCK 还是 MQTT，由 `AT+DTUTASK` / `[task.N]` 决定，路由串本身不选协议。

## 4. 子通道一览

### 4.1 通道 1～4：业务通道上的槽

| 子通道 | 该路是 SOCK 时 | 该路是 MQTT 时 |
| --- | --- | --- |
| `1` | 忽略；整包仍只发到这一路 Socket | `[mqtt.N.publish.1]` 发布槽 |
| `2` | 同上（多写几个槽也不会拆成多路 Socket） | `[mqtt.N.publish.2]` |
| `3` | 同上 | `[mqtt.N.publish.3]` |
| `4` | 同上 | `[mqtt.N.publish.4]` |
| `5` | 同上 | `[mqtt.N.publish.5]` |
| `6` | 同上 | `[mqtt.N.publish.6]` |
| `7` | 同上 | `[mqtt.N.publish.7]` |
| `8` | 同上 | `[mqtt.N.publish.8]` |

`N` 是一级通道号（1～4）。MQTT 配置里还有发布槽 **9、10**（`AT+MQTTPUB` 能配），**路由串写不到**：`1[9]` / `1[10]` 整串非法。

选中的 MQTT 槽若主题为空，该槽本次不发；若选中的槽全部为空，这一路等于没发出去。

### 4.2 通道 5：HTTP

| 子通道 | 指向 |
| --- | --- |
| `1` | HTTP 通道 1（`AT+HTTPURL=1` / `[http.1]`） |
| `2` | HTTP 通道 2 |
| `3` | HTTP 通道 3 |
| `4` | HTTP 通道 4 |
| `5` | HTTP 通道 5 |

`5[6]` 非法。每个选中的 HTTP 通道各发起一次请求，载荷当作请求体（方法 / URL 用该通道已配的值）。

当前写出只把 HTTP **1～4** 真正发出去。`5[5]` 语法合法、能存，但这次不会发到第 5 路。要测第 5 路 HTTP，用 `AT+HTTPREQ=5,…`，不要只靠路由串。

### 4.3 通道 6：UART

| 子通道 | 指向 |
| --- | --- |
| `1` | UART1（常见 AT / 业务口） |
| `2` | UART2 |
| `3` | UART3 |

`6[4]` 非法。没有 UART0。多选则同一份数据各写一遍。

### 4.4 通道 7：短信

| 子通道 | 指向 |
| --- | --- |
| `1` | 短信通道 1（`[sms.1]` 的号码） |
| `2` | 短信通道 2 |
| `3` | 短信通道 3 |
| `4` | 短信通道 4 |
| `5` | 短信通道 5 |
| `6` | 短信通道 6 |
| `7` | 短信通道 7 |
| `8` | 短信通道 8 |
| `9` | 短信通道 9 |
| `10` | 短信通道 10 |

`7[11]` 非法。每个选中且已配号码的通道各发一条**相同正文**。号码为空的通道跳过。

## 5. 省略、默认与查询回显

不写方括号时，只激活该类的子通道 1：

| 写入 | 等价于 | 实际出口 |
| --- | --- | --- |
| `1` | `1[1]` | 业务通道 1（MQTT 则发布槽 1） |
| `5` | `5[1]` | HTTP 通道 1 |
| `6` | `6[1]` | UART1 |
| `7` | `7[1]` | 短信通道 1 |
| `1\|2` | `1[1]\|2[1]` | 业务通道 1 和 2 |

查询、设置成功回显时，会把内部集合**规范化**后再打出来：

| 内部选中 | 回显 |
| --- | --- |
| 只选了子通道 1 | 不带括号：`6`，不是 `6[1]` |
| 只选了子通道 2 | `6[2]` |
| 选了 1 和 2 | `6[1:2]` |
| 多类出口 | 按通道号升序用 `\|` 拼接，例如 `1\|6[2]` |
| 什么都没选 | 空串 `""` |

因此 `AT+HTTPCFG=1,"route","6[1]"` 查回来常常是 `"6"`。含义没变。

## 6. 哪些指令用这套语法

| 指令 | 参数 | 非法时 |
| --- | --- | --- |
| `AT+RTUWRITE` / `AT+RTUWRITEQ` | 第一参路由串 | 短 reason（见 [rtu.md](rtu.md)） |
| `AT+DTUPSUP` | 某路 UART 的**上行**出口 | `"error route_str"` |
| `AT+DTUPSDN` | 某路任务的**下行**出口 | `"error route_str"` |
| `AT+HTTPCFG` | key `route`：HTTP 响应打到哪 | `"error route"` |
| `AT+SMSCFG` | key `forward_route`：收信转发到哪；**必须带双引号** | `+CME ERROR: 109`（没引号是 105） |
| `AT+LBSCFG` | key `tmr_rpt_route`：定位定时上报打到哪；最长 127 | 短 reason / 失败（见 [lbs.md](lbs.md)） |
| `AT+IOTMPLH` | 第二参：IO 模板上报打到哪 | `+CME ERROR: 109` |

空串在多数指令里表示「清空 / 不选出口」，与非法串不同。`LBSCFG` 的空串表示走默认路径，见该篇。

Lua 侧同一套：`rtu.write(route, data)`，见 [rtu API 第 8 节](../api/module/rtu.md#8-路由字符串)。

## 7. 心跳 / 注册包不是这套语法

`AT+DTUHEART` / `AT+DTUREG` 最后一段叫 `channel_str`，写法只有：

```lua
1
1|2
1|3|5
```

数字是**这一路任务自己的 MQTT 发布槽 1～8**，用 `|` 并选，**没有** `[]`，也**没有** 5/6/7 这类出口。写 `6[1]` 不会把心跳打到 UART1。

该路是 SOCK 时，这段列表不改变发送目标：心跳 / 注册包仍发到这一路 Socket。

完整任务指令见 [rtu.md](rtu.md#5-atdtuheart--atdtureg)。

## 8. 非法与失败

整串失败的常见原因：

| 写法 | 原因 |
| --- | --- |
| `0`、`8`、`1\|9` | 通道号不在 1～7 |
| `1[`、`1]`、`[1]` | 括号不成对，或缺少通道号 |
| `1[9]`、`1[10]` | 业务通道子通道超过 8 |
| `5[6]` | HTTP 子通道超过 5 |
| `6[4]` | UART 子通道超过 3 |
| `7[11]` | 短信子通道超过 10 |
| `abc`、`1[x]` | 不是十进制正整数 |

失败码按宿主指令：

| 风格 | 码 / reason | 出现处 |
| --- | --- | --- |
| 短 reason | `route` / `route_str` | HTTP、DTU 上下行、写出 |
| `+CME ERROR` | **109** 路由转换失败 | `SMSCFG`、`IOTMPLH` 等 |

解析成功只表示语法合法，不保证对端已连上、号码已配、HTTP URL 已写。

## 9. 示例

只出 UART1（最常见）：

```lua
6
6[1]
```

UART1 和 UART3：

```lua
6[1:3]
```

业务通道 1 和 2（各用默认槽 1）：

```lua
1|2
```

通道 1 已配成 MQTT，发到发布槽 1、2、3：

```lua
1[1:2:3]
```

通道 1 下行到 UART1，同时抄一份到通道 2：

```lua
2|6[1]
```

HTTP 响应出 UART1（HTTP 通道默认路由）：

```lua
AT+HTTPCFG=1,"route","6[1]"
+HTTPCFG: 1,"route","6[1]"

OK

AT+HTTPCFG=1?
```

查询里 `route` 可能回 `"6"`，与 `"6[1]"` 同义。

收信转到业务通道 1，并在 UART1 打一份：

```lua
AT+SMSCFG="forward_route","1|6[1]"
+SMSCFG: "forward_route","1|6"

OK
```

按路由写裸数据：

```lua
AT+RTUWRITE="6[1]",hello
OK
```

空路由：不选出口，解析成功。

```lua
AT+RTUWRITE="",hello
OK
```
